- **Repository and system admins can override release immutability for one request, with a required reason, and every decision is audited** (#4812). Until now the only way past an `IMMUTABLE_RELEASE` refusal was to be a system admin: the REST delete let one through without a trace, and `?permanent=true` (#4700) let one purge the trash and re-upload. Send `X-Artifact-Keeper-Immutability-Override: true` and `X-Artifact-Keeper-Immutability-Override-Reason: <why>` (visible ASCII, at most 1024 bytes) on `PUT /api/v1/repositories/{key}/artifacts/{path}`, the multipart uploads, the chunked-upload completion, or `DELETE /api/v1/repositories/{key}/artifacts/{path}`. A caller holding the repository `admin` action (directly, through a group, or from the project, the same check the repository-scoped age gate uses) or a system admin can then replace or delete a released artifact. A repository admin can also use `?permanent=true`. Each honoured override records `IMMUTABILITY_OVERRIDDEN` with the reason, the enforcement point and the actor's tier, and it fails closed if the audit row cannot be written. Anyone else who sends the header still gets the 409, and the attempt is recorded as `IMMUTABILITY_DENIED`. The flag without a reason is a 400, whoever sends it. Requests without the header behave exactly as before, including a system admin's implicit delete.
