- **Every release-immutability refusal now answers 409 with the stable code `IMMUTABLE_RELEASE`** (#4812). Refusals used to come in four shapes: `{"code":"CONFLICT"}`, a plain-text body, cargo's `errors` list, and pub's or Swift's own envelopes. None of these could be told apart from a quarantine hold or any other 409 without matching on message text. This covers re-publishing a version that already exists, re-uploading different bytes after deleting a released version, deleting a released artifact through the REST API, and re-publishing an RPM repository version. All of them now carry `IMMUTABLE_RELEASE`. Handlers that answered in plain text (Alpine, Ansible, Bazel, Chef, CocoaPods, Composer, Conda, CRAN, Debian, Go, Helm, Hex, Hugging Face, JetBrains, pacman, Puppet, RPM, RubyGems, sbt, Terraform, VS Code) now return the structured `{"code","message"}` body. Cargo, pub and Swift keep their native envelopes and add the code inside them (`errors[0].code`, `error.code`, and a problem+json `code` member). Message texts are unchanged. Quarantine holds and all other conflicts keep `CONFLICT`. The OpenAPI spec now documents the 409 on `PUT /api/v1/repositories/{key}/artifacts/{path}` and names the code on the delete and chunked-upload-completion 409s. A client that matched `code == "CONFLICT"` to detect an occupied version must also accept `IMMUTABLE_RELEASE`.
